# Agent System X Phase 1 薄集成 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不重构现有 AGX 的前提下，安全安装并通过统一 `agx config` 入口调用上游 `configs` runtime。

**Architecture:** 保留当前 Go AGX 部署控制面和命令语义。将上游 `configs` 作为 Bundle 中固定 source commit、release、平台 artifact 和 SHA-256 的受管 runtime；`agx config --root <dir> ...` 只做 Receipt 校验、受控环境注入和直接 argv 转发，不读取或写入 `configs` SQLite。

**Tech Stack:** Go、现有 AGX Bundle/installer/receipt 代码、GitHub Release artifact、SHA-256、`os/exec`；上游 `configs` runtime 为 TypeScript/Bun 编译的独立可执行文件。

**Spec:** `docs/superpowers/specs/2026-08-26-agent-system-x-merge-design.md`

## Global Constraints

- 保留现有 `agx apply/init/status/diagnose/uninstall` 行为和远端部署能力。
- Phase 1 不复制 `agent-systemX` 源码，不重排 `internal`，不新增双向同步。
- 生产 runtime 必须来自固定 GitHub Release artifact；不得使用上游 `main`、本地 checkout、mutable URL 或未校验二进制。
- Runtime binding 必须包含 version、source commit/tag、platform/architecture、artifact/content SHA-256 和受管安装路径。
- `agx config` 必须直接 argv spawn，不经 shell；stdout、stderr、stdin、退出码和取消信号必须可验证。
- Receipt、日志和支持包不得包含凭据、prompt、transcript、Session、私域原文或工具 payload。
- 旧 Receipt 必须继续可读；未知文件、同名资源和无法证明 ownership 的对象不得删除。
- `verified` 只能由现有 Evidence Profile 的外部证据产生；runtime 安装或子进程退出码为零不能提升为 `verified`。
- 上游没有可用的正式 Release artifact 时，停止生产 pin 和真实安装实现；不得伪造 release 值。

## Plan Self-Review

- **Spec coverage:** The plan covers runtime pinning, installation, Receipt binding, `agx config`, status, uninstall, privacy, failure behavior, platform support, and actual smoke verification. It deliberately defers source co-location, command namespace migration, and bidirectional sync as required by the lean Phase 1 scope.
- **Placeholder scan:** No production hash, release tag, or artifact URL is fabricated. The upstream-release prerequisite is an explicit stop gate, not an implementation placeholder.
- **Type consistency:** `bundle.ConfigsRuntime`/`RuntimeArtifact` feed `install.ConfigsRuntimeReceipt`; `install.Options.TargetPlatform/TargetArch` feed deterministic artifact selection; `cli.runtimeDependencies.configRun` injects the exact runner signature used by `agx config`.
- **Main risk:** The upstream release workflow currently publishes direct binaries, while the existing AGX installer is archive-oriented. Task 2 explicitly handles direct executable artifacts rather than forcing the runtime through the tar extractor.
